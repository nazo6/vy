# [Worklog] マウスによるペイン移動・カーソル移動とホイールのルーティング

- **日付**: 2026-10-30
- **関連フェーズ/タスク**: エディタ UX（ADR 0029 のマウス操作）
- **目的**: 左クリックでペインを切り替え、エディタペインではクリック位置へカーソルを移動できるようにする。ホイールはフォーカスを変えず、ポインタ下のペインをスクロールさせる。

## 作業内容

- `EditorView` にペインごとの描画済み `Bounds` を保持するセルを追加した。クリック位置はウィンドウ座標なので、キャンバスのペイント時に実際の矩形を書き込み、マウスハンドラが読む。
- エディタペインと UI ペインの両方に `on_mouse_down` を付け、クリックしたペインをアクティブにした。ペインが変わったときは `pane/focus` をコアへ送り、クライアントとコアの `active_pane` を揃える。
- エディタペインのクリック位置を `VisualIndex` と同じ規則で文字位置へ変換した。折り返し、横スクロール、タブ、全角文字に対応する。`EntityInputHandler` が使っていた整形テキストのヒットテストを共通のヘルパーへ切り出した。
- `Editor::move_cursor_to` を追加した。選択範囲を解除し、Normal モードでは行末を越えず1文字を選択したままにする。
- ルート要素の `on_scroll_wheel` を外し、エディタペインの領域へ移した。これでホイールはポインタ下のペインだけをスクロールし、フォーカスは変わらない。UI ペインは既存の `overflow_y_scroll` が処理する。
- 左ボタンのドラッグで範囲選択できるようにした。押下位置をアンカーとして保持し、数ピクセル動いた時点で `Select` モードに入り、移動に合わせて head を更新する。動かさずに離した場合はクリックとして扱う。
- `Shift` クリックで現在のカーソル（選択中ならアンカー）から拡張し、ダブルクリックで単語、トリプルクリックで行を選択する API を `Editor` に追加した。単語のまとまりは word motion と同じ文字クラスで、行をまたがない。
- モーダルのオーバーレイが開いている間は、コンテンツ全体に不可視の `occlude` 層を置いた。これで背後のペインはクリックもホイールも受け取らず、オーバーレイ自身の一覧だけがスクロールできる。
- ディバイダーを `occlude` にして、リサイズ開始のクリックが背後のペインのカーソル移動にならないようにした。

## 発生した課題と対処

- マウスイベントは要素ローカルの座標を持たない。キャンバスのペイント時に `Rc<Cell<Option<Bounds<Pixels>>>>` へ矩形を保存し、イベント時に引き算する形にした。
- カーソル位置の変換を固定文字幅で行うとタブと全角文字がずれる。既存の IME 用ヒットテストと同じく `shape_line` と `index_for_x` を使った。
- ホイールのハンドラをルートとペインの両方に置くと二重にスクロールする。ルート側を削除し、スクロール対象をペインごとに限定した。
- モーダル中の UI ペインのスクロールは、ハンドラ側のガードでは止められない。GPUI の組み込みスクロールも止めるため、ペインより前面・オーバーレイより背面に遮蔽層を置いた。
- ドラッグ開始時に `Select` モードへ即座に入ると、単なるクリックでも1文字選択が残る。移動距離のしきい値を超えたときだけ選択を開始するようにした。

## 検証結果・測定値

- `cargo test --workspace`: すべて成功。
- `cargo clippy --workspace --all-targets`: 警告なし。
- `cargo fmt --all --check`、`pnpm format:check`: 成功。
- 追加したテスト: `move_cursor_to` のクランプと選択解除、単語・空白・行をまたぐ境界の単語選択、行選択、`extend_selection_to` のアンカー維持。

## フォローアップ・残課題

- ドラッグ中にペインの外へポインタが出たときの自動スクロール。
- ダブルクリック後のドラッグで単語単位、トリプルクリック後で行単位に選択を広げる操作。
- マウスで作った選択を離した後に `Select` モードを維持する現在の挙動の見直し（離したら Normal に戻す案）。
