# 作業ログ (Worklogs)

アーキテクチャの意思決定（ADR）ではないものの、**着手した**規模の大きな作業（リファクタリング、段階的移行、パフォーマンス改善、調査検証など）の計画と実施ログを記録する場所です。まだ着手していない計画は [`../proposals/`](../proposals/README.md) に置きます。

設計ドキュメントや仕様書が作業詳細メモで肥大化するのを防ぎ、後から「なぜ・どのようにその作業を進めたか」「どのような課題が発生してどう解決したか」を追跡できるようにします。

## 作業ログ一覧

- [`2026-10-editor-ui-improvements.md`](./2026-10-editor-ui-improvements.md): UI・エディタ品質改善ログ

## 命名規則

ファイル名は `YYYY-MM-DD-<slug>.md` とします（例: `2026-10-25-phase2-refactoring.md`）。

## frontmatter テンプレート

```yaml
---
title: "作業ログのタイトル"
type: "worklog"
date: 2026-10-25
phase: "Phase 2" # 任意: 関連するフェーズ
tags: ["refactoring", "gpui"]
---
```

## 本文の構成テンプレート

```markdown
# [Worklog] <作業タイトル>

- **日付**: 2026-10-25
- **関連フェーズ/タスク**: Phase 2
- **目的**: 何のためにこの作業を行うか

## 作業内容

- 実施した変更の手順や要約

## 発生した課題と対処

- 作業中につまずいた点や、予定から変更した点

## 検証結果・測定値

- テスト結果、ベンチマークやパフォーマンスの実測値など

## フォローアップ・残課題

- 次の作業に引き継ぐ項目
```
