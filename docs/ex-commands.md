# Ex コマンド

`:` で開くコマンドライン（Ex コマンド）の設計です。コマンドパレット
（`Space`）とは入口だけを分け、コマンドの解決と実行は共通にします。

コマンド ID、キーバインド、`commands.execute` の関係は [`api.md`](./api.md)
の「コマンドとキーバインド」にあります。パレットの操作は
[`keymap.md`](./keymap.md) の「画面操作」にまとめています。

## 1. 方針

1. Ex は独立したコマンド体系ではありません。登録済みのコマンドを Ex 名で呼ぶ
   フロントエンドです。
2. パレット、Ex、キーマップ、`commands.execute` は同じ `Invocation` を作り、
   同じ実行キューに渡します。
3. `:` はペインではなくクライアントのオーバーレイです。レイアウト木にも保存にも
   含めません（[`panes.md`](./panes.md) の「Overlay」）。
4. 初期の Ex は `[range] name[!] [args]` の形だけを扱います。`|` による連結、
   `"` によるコメント、パターンによる範囲指定は後回しにします。
5. Ex 名はコマンド ID から自動生成しません。明示した別名だけを使います。
6. Ex も `commands.execute` と同じケイパビリティ検査を通します。Ex を権限の
   抜け道にしません。
7. エラーはプロトコルの `ErrorCode` と英語のメッセージで表します。Vim の `E123`
   のような番号を主識別子にはしません（[`development.md`](./development.md)）。

## 2. パレットとの違い

| 項目       | コマンドパレット       | Ex コマンドライン                  |
| :--------- | :--------------------- | :--------------------------------- |
| 開き方     | `Space`                | `:`                                |
| 入力       | あいまい検索する文字列 | `[range] name[!] [args]`           |
| コマンド   | 一覧から選ぶ           | 別名を解決する                     |
| 範囲       | 渡さない               | `range` を渡せる                   |
| `!`        | 渡さない               | コマンドが宣言した場合だけ渡せる   |
| 引数       | 初期版では渡さない     | 生の文字列をコマンドが解釈する     |
| 完了       | 検索結果の絞り込み     | コマンド名、将来は引数のパス       |
| エラー表示 | パレット内             | ステータス行（将来は `:messages`） |

`Space` と `:` は別の入口として残します。パレットの検索欄に `:` を書いたときに
Ex へ切り替えるような兼用は、文法と履歴が混ざるため初期版では行いません。

## 3. データモデル

コマンドは実行方法に依存しない記述子を持ちます。

```text
CommandDescriptor
  id: string                    // vy.pane.split_right
  title: string                 // Split Pane Right
  aliases: [string]             // Ex 名。例: ["sp"]
  source: builtin | init | plugin
  hidden: bool                  // パレットに出さない
  accepts_args: bool
  accepts_range: bool
  accepts_bang: bool
  range_default: none | current_line | selection | whole_document
  completion: none | path | command_name
```

実行はすべて次の形にそろえます。

```text
Invocation
  id: string
  args: InvocationArgs
  range: Range | null
  bang: bool
  source: keymap | palette | ex | script
```

```text
InvocationArgs
  Keymap { count, register }
  Ex { raw }
  Script { value }
  None
```

- キーマップは `count` と `register` を渡します。
- パレットは `None`、`range: null`、`bang: false` を渡します。
- Ex はコマンド名を `id` に解決し、`raw`、`range`、`bang` を渡します。
- `commands.execute` はコマンド ID だけを受け付け、Ex 名は解決しません。 Ex
  名はクライアントの UI 層だけが扱います。
- 実行キューは 1 本にし、実行中のコマンドが終わるまで次を開始しません。

## 4. 画面と入力

`:` は Normal と Select でだけコマンドラインを開きます。Insert では `:`
は文字として入力します。

- 画面下の 1 行に `:` と入力内容、補完候補、エラーを出します。
- 開いている間はエディタのキーマップとモーダル入力へキーを渡しません。
- `Esc` はキャンセル、`Enter` は実行、`Tab` / `Shift-Tab` は補完、 `Up` / `Down`
  は履歴です。
- `Backspace` は 1 文字削除、`Ctrl-u` は行全体の削除です。`Ctrl-u` は
  エディタのアンドゥと衝突するため、コマンドラインが開いている間だけ優先します。
- 日本語入力のために、コマンドラインもクライアントのテキストエンジン （IME
  の前編集）を使います。パレットの入力も同じ仕組みへ寄せます。
- カーソル、選択、モードはペインごとに独立しているため、Ex の範囲と既定行は
  アクティブペインの文書を基準にします。

## 5. 文法

```text
command_line := ":" [range] name ["!"] [space args]
range        := address | address "," address | "%"
address      := number | "." | "$" | "'<" | "'>" | "+" [number] | "-" [number]
```

範囲の文法:

| 指定        | 意味                                             |
| :---------- | :----------------------------------------------- |
| `%`         | 文書全体                                         |
| `N`         | N 行目                                           |
| `.`         | アクティブペインのカーソル行                     |
| `$`         | 最終行                                           |
| `N,M`       | N 行目から M 行目                                |
| `'<` `'>`   | 文書ごとに記録した最後の Visual 範囲             |
| `+N` / `-N` | カーソル行からの相対行（範囲を書いた位置で評価） |

- 範囲はまず行範囲として解決し、クライアントが文字位置の `Range` に変換します。
  コマンドは行単位か選択単位かを自分で決めます。
- `range` を受け付けないコマンドに範囲が付いたら、実行せずエラーにします。
- 範囲の既定値はコマンドごとに宣言します。たとえば `:d` は現在行、 `:w`
  は文書全体、`:e` は範囲を受け付けません。
- 範囲を省略したときに「選択範囲」を使うか「現在行」を使うかは、 `range_default`
  で明示します。暗黙の既定値は置きません。
- 初期版では上の文法を**解析**しますが、`accepts_range` を持つコマンドが現れる
  まで実行は拒否します。文法と実行を同時に広げないためです。

## 6. 名前の解決

- Ex 名は小文字の英字と `-` だけにします。
- 完全一致を最優先します。
- 完全一致がなければ一意に決まる接頭辞を許可します。たとえば `:wri` は `:write`
  に解決します。
- 候補が複数ある場合は実行せず、候補をエラーに並べます。
- コマンド ID（`vy.pane.split_right`）は Ex 名として使いません。Ex 名は
  別名として明示的に登録します。
- 組み込みの Ex 名は予約します。プラグインが同じ名前を登録することはできません。

## 7. 引数と `!`

- `name` の後ろの文字列は、先頭の空白を除いてそのままコマンドへ渡します。
- 引数の解釈はコマンドごとに行います。Ex 側でパスや数値に分解しません。
- `!` はコマンドが `accepts_bang` を宣言した場合だけ渡します。意味はコマンドが
  決めます（例: `:q!` は未保存の変更を捨てる、`:w!` は上書きする）。
- `accepts_bang` のないコマンドに `!` が付いたらエラーにします。
- `|` による複数コマンドの連結は初期版では扱いません。`:wq` のような組み合わせは
  1 つのコマンド（例: `vy.document.write_and_quit`）として登録します。

## 8. 組み込みの Ex 名

ビルトインのコマンドには、次の別名を付けます。状態は別名ではなく、対応する
コマンドの実装状況です。

| Ex 名    | コマンド ID                 | 状態   | 備考                          |
| :------- | :-------------------------- | :----- | :---------------------------- |
| `:sp`    | `vy.pane.split_down`        | 予定   | 上下に分割                    |
| `:vsp`   | `vy.pane.split_right`       | 予定   | 左右に分割                    |
| `:close` | `vy.pane.close`             | 予定   | 最後のペインは閉じられない    |
| `:q`     | `vy.pane.close`             | 予定   | 最後のペインでの意味は未決定  |
| `:e`     | `vy.editor.open`            | 未実装 | 引数に URI またはパスを取る   |
| `:w`     | `vy.document.save`          | 未実装 | 引数のパスは未対応            |
| `:wq`    | `vy.document.write_quit`    | 未実装 | 保存と終了を 1 コマンドにする |
| `:bn`    | `vy.document.next`          | 未実装 | 文書一覧ができてから          |
| `:bp`    | `vy.document.previous`      | 未実装 | 文書一覧ができてから          |
| `:noh`   | `vy.search.clear_highlight` | 未実装 | 検索のハイライトを消す        |

初期版では、すでに実装済みのペイン操作に別名を付けるところから始めます。
`document.save` や `editor.open` ができる前に `:w` / `:e` の UI だけを先に
作らない方針です。

`!` 付きの強制終了（`:q!`）、シェル実行（`:!`）、`:terminal` は初期版では
扱いません。`:!` は `process:exec` の承認が必要になるため、Ex の権限経路が
固まってから追加します。

## 9. 補完と履歴

- `Tab`: コマンド名の補完。完全一致しなければ最長共通接頭辞まで補完し、
  候補が複数あるときは候補を表示します。もう一度 `Tab`
  を押すと候補を巡回します。
- `Shift-Tab`: 逆方向に巡回します。
- 引数の補完はコマンドの `completion` で宣言します。`path` は将来ファイル一覧を
  コアへ問い合わせます。初期版はコマンド名の補完だけです。
- 履歴はセッション内だけ保持します。`Up` / `Down` で移動し、空行や重複は
  正規化します。ファイルへの永続化は未決定です。
- パレットの検索履歴と Ex の履歴は別に持ちます。実行したコマンドの履歴は
  将来共有を検討します。

## 10. 実行とエラー

1. `:` が開き、入力が確定する。
2. Ex パーサーが範囲、名前、`!`、引数を取り出す。
3. 別名をコマンド ID に解決する。
4. `CommandDescriptor` の宣言と照合する（範囲、`!`、引数）。
5. `Invocation` を作り、実行キューへ積む。
6. コマンドが失敗したら `ErrorCode` とメッセージをステータス行へ出す。

- 解析エラー、未知のコマンド、曖昧な名前、未対応の範囲は、コマンドを実行せずに
  エラーにします。
- コマンドの実行中は入力を待たせ、二重実行を防ぎます。
- コマンドが文書やレイアウトを変える場合、確定はコアの応答を待ちます。 Ex
  の入力行自体はクライアントが描きますが、文書とレイアウトは確定した状態を
  描きます。

## 11. 状態の所在

- Ex の入力行、履歴、補完候補、実行キューはクライアントが持ちます。
- 範囲の行番号と `'<` / `'>` の解決もクライアントが行います。本文の写しと
  ペインごとのカーソルを持っているためです。
- 文書、アンドゥ、レイアウト、ファイル操作はコアが正です。Ex 専用の RPC は
  追加しません。既存のコマンド経由で要求します。
- ケイパビリティの承認は `commands.execute` と同じ経路で確認します。

## 12. 実装状況

| 項目                                      | 状態     |
| :---------------------------------------- | :------- |
| コマンドパレット（`Space`）               | 実装済み |
| 共通の `CommandDescriptor` / `Invocation` | 未実装   |
| `:` のオーバーレイ                        | 未実装   |
| Ex 名の解決と一意の接頭辞                 | 未実装   |
| 組み込みの Ex 別名                        | 未実装   |
| 範囲の解析と実行                          | 未実装   |
| コマンド名の補完                          | 未実装   |
| コマンドラインの履歴                      | 未実装   |
| `commands.execute` の戻り値               | 未実装   |

実装は次の順に進めます。

1. `CommandDescriptor` と `Invocation` を追加し、キーマップ・パレット・
   `commands.execute` を同じ実行関数へ寄せる。
2. `:` のオーバーレイと Ex
   パーサーを追加し、既存のペインコマンドに別名を付ける。
3. `editor.open` / `document.save` を追加して `:e` / `:w` を有効にする。
4. 範囲を受け付ける編集コマンドを追加する。
5. 補完、履歴、プラグインの Ex 別名を追加する。

## 13. 未決定事項

- 最後のペインで `:q` を押したとき、アプリを終了するかエラーにするか。
- `init.ts` や外部プラグインが Ex 別名を登録できるようにするか。登録する場合の
  API と衝突規則。
- `|` による連結、`"` によるコメント、`/pattern/` を使った範囲指定を入れるか。
- 範囲の既定値を「現在行」「選択範囲」「文書全体」のどれにするか（コマンドごと
  に決めるか、共通の既定を置くか）。
- Select モードで `:` を押したときに `'<,'>` を自動で補うか。
- Ex の履歴をファイルへ保存するか、パレットと共有するか。
- コマンドラインの IME
  対応と、パレットの入力を同じテキストエンジンへ寄せる時期。
- `:!` を許可する場合のケイパビリティと、シェル展開の範囲。
- Ex 名の大文字・小文字を区別するか（初期案は小文字のみ）。
