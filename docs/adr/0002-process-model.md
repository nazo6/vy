# ADR 0002: クライアントとコアを常に別プロセスにする

- 状態: 採用
- 日付: 2026-10-22

## 文脈

Vy は、GPUI
で描くクライアントと、文書、検索、言語サーバーを持つコアを分けています。コアはローカルにもリモートにも置けます。

このとき、ローカル接続だけ同一プロセスにすると、メモリを共有する近道ができます。しかし、その近道はリモートでは使えません。同じ
API が接続先によって違う経路を通ると、リモートでだけ壊れる箇所が残ります。API
の実行場所を書くときにも、何を基準にするのかが決まりませんでした。

## 決定ドライバ

1. API の意味を接続先で変えないこと。
2. ローカルの開発中に、リモートと同じ経路を検証できること。
3. コアのクラッシュがクライアントを巻き込まないこと。
4. コアを単体で起動してテストできること。
5. 入力の遅延を増やさないこと。

## 検討した選択肢

| 選択肢                 | 内容                                            | 問題                                                     |
| :--------------------- | :---------------------------------------------- | :------------------------------------------------------- |
| 常に別プロセス         | ローカルでも子プロセスを起動する                | プロセスが1つ増え、起動と IPC の費用がかかる             |
| ローカルは同一プロセス | 関数呼び出しでコアを呼ぶ                        | リモートでだけ通る経路が残る。API の意味が接続先で変わる |
| ビルドで切り替え       | feature フラグで同一プロセスと RPC を切り替える | 2つの経路を保守することになり、片方が腐る                |

## 決定

クライアントとコアは常に別プロセスにします。

- クライアントは `vy-app`、コアは `vy-server` です。
- ローカル接続では、クライアントが `vy-server`
  を子プロセスとして起動し、標準入出力で RPC を流します。
- リモート接続では、SSH の先で `vy-server` を起動し、同じ形式の RPC を流します。
- 同一プロセスでコアを呼ぶ近道は作りません。`vy-core`
  をクライアントにリンクしません。

## 帰結

### 良い面

- API が常に RPC を通るため、ローカルの開発中にリモートの経路を検証できます。
- コアが落ちてもクライアントは落ちません。再接続して状態を戻せます。
- `vy-server` を単体で起動し、GUI なしでテストできます。
- 実行場所の列を「状態の正を持つ層」として定義できます。

### 悪い面

- 起動するプロセスが1つ増えます。
- すべての呼び出しに IPC の費用がかかります。
- 不具合の切り分けで、2つのプロセスのログを見る必要があります。

### 緩和策

- 起動時は `initialize` の往復を1回だけにし、重い初期化は後から行います。
- ローカルは標準入出力を使い、ソケットの設定を省きます。
- ログにプロセス名とセッション ID を付け、1つの画面で追えるようにします。
- 開発中は `vy-server` を別の端末で起動できるようにします。

## 見直しの条件

次のどれかに当てはまったら見直します。

1. ローカル接続で、入力から描画までの遅延が目標を超え、RPC
   が主な原因だと分かった。
2. 起動時間のうち、子プロセスの起動が2割を超えた。

見直す場合も、同一プロセスに戻すのではなく、共有メモリや転送形式の圧縮を先に検討します。

## 関連する未決定事項

- `vy-server` の起動引数とワークスペースの指定方法: `--stdio`
  だけを引数にし、ワークスペースは `initialize` で渡すことにしました（[`protocol.md`](../protocol.md)）。
- 子プロセスの終了: クライアントは通知だけを出し、自動では再起動しないことにしました（[`architecture.md`](../architecture.md)）。
- 標準入出力と Unix ソケット: 当面は標準入出力だけを使います。ソケットと名前付きパイプは、多重化を決めるときに扱います。
