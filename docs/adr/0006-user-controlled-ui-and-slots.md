# ADR 0006: ユーザー制御 UI とスロットによるステータスライン

- 状態: 採用
- 日付: 2026-10-22

## 文脈

初期のプロトタイプ（Phase 1〜2）では、クライアント（`vy-app`）内に固定のヘッダー（バージョン・状態表示）、フッター（モード・行桁・ペイン番号）、ペイン上部のタイトルバー、およびウィンドウ外枠のパディング（`p_4` / `gap_2`）がハードコードされていました。

しかし、Vy のコア方針はモーダル編集と高い拡張性であり、エディタ画面の領域を最大限に活用できること、そして画面上のクローム（装飾・情報バー）を利用者やプラグインが完全に制御できることが求められます。ハードコードされた UI は不要な領域を占有し、利用者が消したり並び替えたりすることができません。

Phase 3 ではスロット（Slot）機能の導入を予定しています。これに合わせて、固定の既定 UI を全廃し、スロットを通じた「完全にユーザー制御された UI」へと移行します。

## 決定ドライバ

1. **画面領域の最大活用**: 余分な外枠パディングや不要な固定バーを排し、Neovim や Helix のようなミニマルで画面全域を使える編集体験を提供すること。
2. **完全なユーザー制御**: ステータスラインなどの UI 要素を、設定（`init.ts`）やプラグインから自由に追加・更新・非表示にできること。
3. **親しみやすい既定表示**: 特別な設定をしなくても、標準 Vim のように必要最小限で実用的な情報（モード、ファイル名、変更状態、カーソル位置）が最初から表示されること。
4. **段階的・シンプルな実装**: 複雑化を避け、まずはウィンドウ最下部の「グローバルステータスライン」1本に集約してスロット基盤を確立すること。

## 検討した選択肢

| 選択肢 | 内容 | 評価 |
| :--- | :--- | :--- |
| **A. クライアント固定 UI の維持・設定フラグ追加** | Rust 側にヘッダー・フッター・タイトルバーを持ち続け、オン/オフの設定フラグを追加する | 一見手軽だが、表示項目の並び替えやプラグイン独自の項目追加（Gitブランチ、LSPステータス等）に対応できず拡張性が損なわれる。 |
| **B. 最初からペイン毎とグローバルの両方をサポート** | 各ペイン個別ステータスラインとウィンドウ全体のグローバルステータスラインを同時にスロット化する | 将来有用だが、初期段階ではペイン管理やレイアウト計算の複雑度が増す。まずはグローバルで十分。 |
| **C. 固定 UI を全廃しグローバルスロットに移行（採用）** | 固定ヘッダー/フッター/パディングを全廃。スロット API (`ui.statusline`) を導入し、標準 Vim 風の最小表示をデフォルトとする | 画面がすっきりし、利用者が `init.ts` から完全に外観を制御できる。段階的移行として最もバランスが良い。 |

## 決定

1. **固定 UI の全廃と画面全域の利用**:
   - ウィンドウ全体のハードコードされたヘッダー、フッター、外枠パディング（`p_4`、`gap_2`）を廃止します。
   - ペイン上部の個別タイトルバーも廃止し、ペインの区切りはシンプルな境界線（アクティブペインの枠線ハイライト）のみとします。
2. **グローバルステータスラインの採用**:
   - ウィンドウ最下部に 1 行の「グローバルステータスライン」を配置します。
   - 当面はペイン毎のステータスラインは持たず、グローバルステータスラインのみとします。
3. **スロットによる動的構成**:
   - ステータスラインはスロット（Slot）として実装します。
   - スクリプト側（`init.ts` やプラグイン）から `ui.statusline.createItem` などの API を通じて、配置位置（左・中央・右）、優先度、テキスト、色トークン、クリック時コマンドを動的に登録・更新できるようにします。
4. **標準 Vim 風の最小限のデフォルト表示**:
   - ユーザーが独自設定をしない場合でも、標準 Vim に近い以下の最小構成をデフォルトとして提供します：
     - **左側**: モード（`NORMAL` / `INSERT` / `SELECT`）、ファイルパス、変更状態（`[+]`）
     - **右側**: カーソル位置（`行:列`）、文書内の現在位置割合（`Top` / `XX%` / `Bot`）
   - これらデフォルト項目もスロット経由で構築され、ユーザーは自由に無効化・差し替えが可能です。

## 帰結

### 良い面
- エディタの表示領域が広がり、ノイズのない洗練されたモダンな見た目になります。
- ユーザーが自分好みのステータスライン（Neovim の lualine 風、あるいは完全非表示など）を `init.ts` から容易に構築できます。
- 将来の Git 状態、LSP エラー数などのプラグイン情報も同じスロット API を使って自然に表示できます。

### 悪い面・課題
- スロットのデータ同期機構（QuickJS と GPUI 間でのアイテム管理や再描画イベント）の実装が必要になります。
- 複数ペインを分割した際、アクティブでないペインのファイル名が常時見えなくなるため、ペイン切り替え時やファイル検索時の認知を補助する工夫（境界線やピッカー等）が重要になります。

## 見直しの条件

- 多数のペインを並行して編集する運用において、各ペインのファイル名や状態を一目で確認したいという要求が高まり、ペイン毎ステータスライン（Vim の `laststatus=2` 相当）が必要になった場合。

## 関連する未決定事項

- ペイン毎ステータスラインのサポート時期と、グローバルステータスラインとの切り替え設定（`ui.statusline.mode: "global" | "per-pane" | "none"`）。
- ステータスライン上のクリックイベントのサポートとコマンドディスパッチ。
