# ADR 0004: アンドゥの履歴はコアが持つ

- 状態: 採用
- 日付: 2026-10-22
- 置き換え: [ADR 0003](./0003-editor-state.md)
  の「アンドゥの履歴はクライアント」を置き換えます。

## 文脈

ADR 0003
では、カーソルと選択をクライアントに置く方針に合わせて、アンドゥの履歴もクライアントに置きました。選択を一緒に戻すには、その方が素直だったためです。

しかし Vy
は、言語サーバーをコアに置きます。整形やリネームの編集は、コアが起こします。複数ファイルにまたがる置換も同じです。クライアントの履歴はキー入力しか知らないため、これらの編集は履歴の外に出ます。日常的に使う操作が戻せない状態になります。

複数クライアントからの同時編集は対象外にしたため、履歴を1か所に集めても衝突は起きません。

## 決定ドライバ

1. コアが起こした編集も戻せること。
2. 複数ファイルの変更を1回で戻せること。
3. 文書ごとに1つの履歴にすること。
4. カーソルと選択を、クライアントに置いたままにすること。
5. キー入力の遅延を増やさないこと。

## 検討した選択肢

| 選択肢           | 内容                                       | 問題                                         |
| :--------------- | :----------------------------------------- | :------------------------------------------- |
| クライアント     | キー入力の履歴だけを積む                   | 整形やリネーム、複数ファイルの置換を戻せない |
| コア（履歴のみ） | コアが履歴を持ち、選択はクライアントが渡す | 選択の受け渡しを取り決める必要がある         |
| コア（状態も）   | カーソルもコアが持つ                       | キー入力のたびに往復が入る                   |

## 決定

アンドゥの履歴はコアが持ちます。カーソルと選択はクライアントに置いたままです。

- クライアントは、編集のトランザクションを送るときに、編集の前後の選択を一緒に渡します。
- コアは、本文の逆編集と、前後の選択を1つの項目として文書ごとに積みます。
- アンドゥとリドゥは、コアが逆の編集と選択を返し、クライアントが適用します。
- コアが起こした編集（整形、リネーム、複数ファイルの置換）も、同じ履歴に入ります。
- 再同期で本文を送り直したときは、その文書の履歴を捨てます。版が合わない履歴は使えないためです。

## 帰結

### 良い面

- どの経路で起きた編集でも、同じ操作で戻せます。
- 複数ファイルにまたがる変更を、1回のアンドゥで戻せます。
- 文書ごとに履歴が1つなので、同じ文書を複数のペインで開いても履歴が分かれません。
- 履歴を保存すれば、クライアントを再起動しても続きから戻せます。

### 悪い面

- アンドゥとリドゥに1往復が入ります。
- 編集のたびに選択を渡すため、メッセージの項目が増えます。
- コアが逆編集を保持するため、履歴の上限を決める必要があります。

### 緩和策

- アンドゥは離散的な操作なので、往復の遅延は入力ほど問題になりません。
- 選択は位置の配列だけなので、1回あたりの大きさは小さいままです。
- 履歴の上限を設け、超えた分は古いものから捨てます。

## 見直しの条件

1. アンドゥの往復が、操作として待たされる程度に遅くなったとき。
2. 履歴の保持でコアのメモリが問題になったとき。

## 関連する未決定事項

- 履歴をセッションをまたいで保存するか。
- 連続した入力を1つのアンドゥにまとめる単位。時間か、入力の種類か。
- 履歴の上限をいくつにするか。
