# ADR 0017: CLI 引数の解析に usage-rs を使う

- 状態: 採用
- 日付: 2026-10-24

## 文脈

`vy-app`、`vy-server`、`vy-api-codegen` は、それぞれ `std::env::args` を手で
走査して引数を解析していました。

- `vy-app` は `--connect` / `-c` と 1 つのファイルだけを扱い、`--help` と
  `--version` を持ちませんでした。
- `vy-server` は `--stdio`、`--version`、`--help` を独自の `HELP` 文字列で
  表示していました。
- `vy-api-codegen` は `--check` と位置引数 `client` を独自に解析し、ヘルプも
  手書きしていました。

同じ規則（不明なオプションは終了コード 2、`-h` / `--help` は標準出力、
`--version` は `{bin} {version}`）を 3 か所で維持する必要があり、バイナリを
増やすたびに同じ実装を繰り返す状態でした。

## 決定ドライバ

1. 引数の宣言とヘルプを 1 か所にまとめ、バイナリ間で規則を揃えること。
2. 終了コードとエラー表示を、一般的な CLI と同じ形にすること。
3. 引数の解析だけを置き換え、起動後の処理（`startup_for`、RPC、生成）を
   変えないこと。
4. 依存を増やす量を小さく保つこと。

## 検討した選択肢

| 選択肢              | 内容                                             | 評価                                                 |
| :------------------ | :----------------------------------------------- | :--------------------------------------------------- |
| A. 手書きのまま     | 各 `main` で引数を走査する                       | 依存は増えないが、ヘルプと規則が重複する             |
| B. clap             | 事実上の標準。derive で宣言できる                | 機能は十分だが、この用途には大きい                   |
| C. usage-rs（採用） | `usage` 仕様から derive で解析・ヘルプを生成する | 宣言が短く、ヘルプ・終了コード・仕様出力を揃えられる |

## 決定

`usage-rs` をワークスペースの依存に追加し、3 つのバイナリの引数解析を derive
に置き換えます。バージョンはワークスペースの `Cargo.toml` で指定します。

- `vy-app`: `CliOptions` に `#[derive(usage_rs::Cli)]` を付け、`--connect` /
  `-c` を `Option<String>`、ファイルを位置引数にします。`main` は
  `CliOptions::parse()` を呼び、ヘルプ・バージョン・解析エラーの表示と終了を
  任せます。`startup_for` のエラー処理は変えません。
- `vy-server`: `--stdio` を持つ `Cli` を定義し、`Cli::parse()` で `--help` と
  `--version` を処理します。標準出力を RPC に予約する説明は `after_help`
  に置きます。
- `vy-api-codegen`: `--check` と位置引数 `surface` を `Cli` に宣言し、
  `choices("client")` で候補を示します。手書きのヘルプは削除します。

引数の解析結果を受け取った後の処理は、これまでどおり各バイナリに残します。

## 帰結

### 良い面

- ヘルプ、`--version`、不明なオプションのエラー表示が 3 つのバイナリで揃う。
- 引数の宣言が型と属性で読みやすくなり、手書きの走査がなくなる。
- 各バイナリが `__usage_spec__` で自身の仕様を出力でき、将来ドキュメントや
  補完を生成できる。

### 悪い面

- CLI の解析に外部クレートが加わる。
- エラーメッセージの文言が usage-rs の形式になり、以前の `vy: ...` /
  `unknown argument: ...` とは変わる。

### 緩和策

- 解析結果を使う処理はバイナリ側に残し、クレートへの依存を引数の解析だけに
  限定する。
- 起動後のエラー（接続プロファイルが見つからない、生成に失敗した）は、これまで
  どおり各バイナリの接頭辞付きで表示する。

## 見直しの条件

1. usage-rs が対応しない引数の形（対話的な入力や独自の補完）が必要になったとき。
2. バイナリの起動時間やバイナリサイズが問題になったとき。
3. CLI の宣言を仕様ファイル（KDL）から生成したくなったとき。
