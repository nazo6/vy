# ADR 0003: 編集状態をコアとクライアントに分ける

- 状態: 採用（アンドゥの所在は [ADR 0004](./0004-undo-in-core.md) で置き換え）
- 日付: 2026-10-22

## 文脈

テキストエディタの状態には、本文のように文書に属するものと、カーソルや選択のように操作の途中で変わるものがあります。両方をコアに置くと、コアが唯一の正になります。両方をクライアントに置くと、入力の遅延を抑えられます。

Vy
はリモート接続を前提にし、入力の遅延を性能の目標にしています。同時に、同じ文書を複数のペインで開き、セッションを復元します。

## 決定ドライバ

1. キー入力から描画までの遅延を、接続先に依存させないこと。
2. 同じ文書を複数のペインで開いても、本文がずれないこと。
3. セッションを復元したとき、文書とレイアウトが戻ること。
4. 言語サーバーに渡す位置が、要求の時点で正しいこと。
5. アンドゥで本文と選択が一緒に戻ること。

## 検討した選択肢

| 選択肢             | 内容                                 | 問題                                                       |
| :----------------- | :----------------------------------- | :--------------------------------------------------------- |
| すべてコア         | カーソルも選択もコアが持つ           | 1文字動かすたびに往復が入る。リモートで遅延になる          |
| すべてクライアント | 本文もクライアントが持つ             | 複数ペインと接続で本文がずれる。ファイルはコアの環境にある |
| 分ける             | 本文はコア、入力の状態はクライアント | 状態の境界を決める必要がある                               |

## 決定

状態を次のように分けます。

| 状態                                           | 持つ場所     |
| :--------------------------------------------- | :----------- |
| 本文、version、ファイル                        | コア         |
| カーソル、選択、モード、スクロール、折りたたみ | クライアント |
| ペインの構成、フォーカス、ウィンドウ           | コア         |
| 診断、構文、Git の状態                         | コア         |
| IME の前編集                                   | クライアント |
| アンドゥの履歴                                 | クライアント |

アンドゥの行は [ADR 0004](./0004-undo-in-core.md)
で置き換えました。以降の記述のうち、アンドゥに関する部分は 0004
を参照してください。

- 編集はクライアントが先に適用し、`base_version` を付けてコアへ送ります。
- コアが受け付けない場合は本文を送り直し、カーソルは再同期の結果に合わせます。このとき、その文書のアンドゥ履歴は捨てます。
- コアに位置が要る操作（補完、ホバー、LSP、整形）は、呼び出しのたびに位置を渡します。常時は同期しません。
- アンドゥは、本文の変更と選択の組をクライアントが積みます。コアは本文と version
  だけを保ちます。

以下は、この ADR を決めた時点の記録です。アンドゥに関する記述は 0004
で置き換えました。

## 帰結

### 良い面

- カーソル移動とモードの切り替えが、接続先の遅延を受けません。
- ペインごとに独立した選択を持てます。同じ文書を2つ開いても干渉しません。
- 言語サーバーには、要求のたびに現在の位置を渡すため、位置のずれが起きません。

### 悪い面

- コアはカーソルを知りません。コア側のプラグインからは、選択を直接読めません。
- アンドゥの履歴がクライアントにあるため、クライアントを変えると履歴が途切れます。
- 再同期が起きたとき、アンドゥ履歴を捨てる必要があります。

### 緩和策

- コア側のプラグインが選択を必要とする場合は、`editor.selections()` を RPC
  で問い合わせます。頻繁に呼ばない前提にします。
- 最後にカーソルがあった位置を、ファイルごとにクライアントの保存領域へ記録します。開き直したときに復元します。

## 見直しの条件

複数クライアントからの同時編集は、現時点では対象外です。対象にするときは、1番を見直します。

1. 同じ文書を複数のクライアントから同時に編集できるようにするとき。この場合は、カーソルと選択の共有方法を決め直す必要があります。
2. コア側のプラグインが選択を頻繁に必要とし、RPC
   の往復が無視できなくなったとき。

## 関連する未決定事項

- カーソル位置と折りたたみを保存する単位。表示中はペインごとに独立とします。保存はファイルごとの最後の位置を基本にし、ペインごとに持つかは未定です。
- アンドゥの履歴をセッションをまたいで保存するか。
- 再同期のときに、アンドゥ履歴を捨てずに移せるか。
