# ADR 0022: コマンドの入口と設定の分離

- 状態: 採用
- 日付: 2026-10-25

## 文脈

Phase 3 でコマンドパレット（`Space`）と Ex コマンドライン（`:`）を同じ
`Invocation` と実行キューに載せました。実行経路は共通になったものの、入口ごとの
見え方と情報源は揃っていません。

- パレットは `CommandRegistry::descriptors()` をそのまま並べるため、
  `vy.motion.left` や `vy.text_object.word` のようなキー専用のプリミティブまで
  表示されます。一方で `vy.editor.open` は hidden になり、引数を渡せません。
- Ex 名は `EX_ALIASES` という別テーブルで解決しています。 `CommandDescriptor` は
  `aliases` を持ちますが常に空で、パレットには出ません。
- 同じ操作が両方に現れます。たとえば折り返しは `:wrap` と `View Toggle Wrap`
  の2か所から実行でき、状態は `settings.json` の
  `editor.wrap`、ペインごとの上書き、コマンドの3経路で変わります。
- Ex は `:set` を持たず、実行中に設定を変える手段がありません。

このままコマンドを増やすと、入口ごとに別の規則を覚える必要が生じます。利用者が
「どの入口で何ができて、どこで状態が変わるか」を予測できなくなる前に、役割と
情報源を決めます。

## 決定ドライバ

1. 3つの入口の違いを1文ずつで説明できること。
2. コマンドを追加するときに直す場所が1か所であること。
3. 発見性（名前を知らなくても使える）と正確性（名前と引数で指定できる）の両立。
4. キーマップの表現力（count、レジスタ、プリミティブ）を落とさないこと。
5. 実行経路とケイパビリティ検査を入口で分岐させないこと。
6. 段階的に移行でき、途中の状態でも壊れないこと。

## 検討した選択肢

| 選択肢                                     | 内容                                                                       | 評価                                                                 |
| :----------------------------------------- | :------------------------------------------------------------------------- | :------------------------------------------------------------------- |
| A. 3入口の役割分担と単一記述子（採用）     | パレット＝発見、Ex＝指定、キー＝反復。メタデータはコマンド定義に同居させる | 学習の負担が小さく、追加時の修正が1か所で済む                        |
| B. パレット中心にして Ex を最小化する      | 日常操作はパレットだけにし、Ex は `:e` `:w` 程度に縮小する                 | 発見性は上がるが、名前で正確に指定する手段とスクリプトの短縮名を失う |
| C. Ex を中心にして Vim に寄せる            | すべての操作に Ex 名を付け、パレットは補助にする                           | Vy 固有の機能まで Ex 名に押し込み、パレットの利点が減る              |
| D. 検索欄で `:` を書いたら Ex に切り替える | `Space` と `:` を1つの入力欄に統合する                                     | 入力の意味が先頭文字で変わり、文法・履歴・補完が混ざる               |
| E. 別名テーブルを維持する                  | パレット用と Ex 用の一覧を分けたままにする                                 | コマンド追加のたびに2か所を直す必要があり、今回の混乱の原因そのもの  |

## 決定

### 1. 実行モデル

キーマップ、パレット、Ex、`commands.execute` は、すべて同じ `Invocation`
を作り、
同じ実行キューとケイパビリティ検査を通します。入口が変えるのは引数の集め方と
入力の補助だけで、コマンドの意味は変えません。

### 2. 入口の役割

| 入口                | 役割                                     | 引数の取り方                                     | 向いている操作                     |
| :------------------ | :--------------------------------------- | :----------------------------------------------- | :--------------------------------- |
| パレット（`Space`） | 何ができるか分からないときに探す         | 選択後に1行プロンプトまたはピッカー              | 初めて使う操作、たまに使う操作     |
| Ex（`:`）           | 名前を覚えているとき、正確に指定するとき | `[range] name[!] [args]`。ArgSpec で型付きに変換 | 繰り返す編集、スクリプト、範囲指定 |
| キーマップ          | よく使う操作を反復する                   | キー列、count、レジスタ、任意の引数              | 移動、編集、ペイン操作             |

- パレットの検索欄に Ex の文法を持ち込みません。`Space` と `:` は別の入口の
  ままにします。
- パレットの各行には Ex 名を併記し、同じコマンドを Ex でも呼べることを示します。
- 設定は入口ではなく状態です。変更はコマンド（`vy.setting.*`）経由に統一し、 Ex
  の `:set` と Settings パレットはそのコマンドを作るフロントエンドにします。

### 3. 単一の記述子

コマンドのメタデータは `CommandDescriptor` に集約し、コマンド ID を定義する enum
と同じ場所（`crates/vy-client-api/src/command.rs`）に置きます。

```text
CommandDescriptor
  id
  title                 // パレットに出す人間向けの名前
  category              // File / Edit / Selection / View / Pane / App / Settings / Plugin
  palette               // listed / hidden
  ex_names              // Ex 名（複数可、無しも可）
  args                  // ArgSpec
  range                 // 受け付ける範囲。none なら範囲付きの実行を拒否する
  bang                  // `!` を受け付けるか
  source                // builtin / pane / ui / init / plugin
```

- 各 enum は網羅 `match` で `meta()` を実装し、variant
  を追加したときの宣言漏れを コンパイルエラーにします。
- Ex 名の別テーブルは作りません。`EX_ALIASES` は削除します。
- パレット、Ex、`commands.getCommands` は同じ記述子から生成します。
- 引数は `ArgSpec` で宣言し、Ex の生文字列、パレットのプロンプト、
  `commands.execute` の JSON、キーマップの引数を同じ検証に通します。コマンドの
  実装が生文字列を独自に解釈する経路は残しません。

### 4. パレット

- 掲載するのは、単体で意味が通る利用者向けの操作だけです。motion、operator、
  text object、insert 系など、キー列の一部として使うプリミティブは hidden に
  します。hidden のコマンドもキーマップ、スクリプト、`commands.execute` からは
  実行できます。
- カテゴリをグループ見出しとして表示し、右側に Ex 名を出します。
- 引数が必要なコマンドは、選択後に1行プロンプトまたはピッカーで引数を取ります。
  引数が無いコマンドはそのまま実行します。
- 検索は完全一致、単語先頭一致、部分一致の順に並べ、最近使ったコマンドを
  セッション内で先頭に出します。
- 設定は Settings ビューに集約し、コマンド一覧にトグルを重複して並べません。

### 5. Ex

- 利用者向けのコマンドには短い Ex 名を付けます。入口そのもの
  （`vy.ui.command_palette`、`vy.ui.ex_command_line`）と内部の糖衣
  （`vy.view.toggle_wrap`）は例外とし、hidden・Ex 名なしにします。
- 完全一致を最優先し、一意に決まる接頭辞を許可します。候補が複数なら実行せず、
  候補を並べます。
- 組み込みの Ex 名は予約します。信頼済みのプラグインは Ex 名を登録できますが、
  小文字英数字と `-` に限り、組み込みと他のプラグインを含めて重複を許しません。
  衝突したプラグインは読み込まず、警告を出します。
- 範囲は文法として解析し、`range` を宣言していないコマンドに付いた場合は実行前に
  エラーにします。範囲を実際に使う編集コマンドは別の決定で追加します。
- 補完は記述子の Ex 名と設定キーから作ります。引数の補完（パスなど）は将来追加
  します。

### 6. 設定

- 設定は状態、コマンドは操作です。
- 設定にはスコープを持たせます。`global` はアプリ全体、`window` はペインごとに
  上書きできる設定です。`editor.wrap` は `window` にします。
- 解決順は「ウィンドウの上書き → メモリ層（`config.set`）→ プロジェクト →
  ユーザー → 既定値」とします。
- `:set` は現在のウィンドウの値を変えます。`window` スコープならウィンドウの
  上書き、`global` スコープならメモリ層を変えます。
- `:setglobal` は `window`
  スコープの新しいウィンドウに対する既定値（メモリ層）を 変えます。
- 実行中に `settings.json` を書き換えません。恒久的な変更は `settings.json` と
  `init.ts` で行います。設定 UI からファイルへ保存するかは別に決めます。
- Settings パレットは `:set`
  と同じ解決ロジックを使い、実効値と、その値がどの層に あるかを表示します。

### 7. キー専用のプリミティブ

motion、operator、text object、insert 系、モード切替は、キーマップとスクリプトの
ためのプリミティブとして残します。パレットには出さず、Ex 名も付けません。
これらを利用者向けの操作に昇格させるときは、別のコマンドとして定義します。

## 帰結

### 良い面

- コマンドを追加するときに、ID、タイトル、カテゴリ、Ex 名、引数を1か所で宣言
  できます。
- パレットが「できることの一覧」になり、キー専用の内部コマンドで埋まりません。
- 同じ操作をパレット、Ex、キーマップ、スクリプトから同じ意味で呼べます。
- 折り返しのような状態が1つの設定に集約され、入口による値のずれがなくなります。
- Ex 名がパレットに出るため、パレットから Ex を覚えられます。

### 悪い面・課題

- `CommandDescriptor` と各 enum のメタデータが大きくなります。
- 引数付きのコマンドは、パレットで選択したあとに追加の入力が必要になります。
- 設定の変更がセッション／ウィンドウ限りであることを、利用者に説明する必要が
  あります。
- 移行は複数の crate と生成物にまたがります。

### 緩和策

- メタデータは網羅 `match` とテストで漏れを防ぎます。Ex 名の一意性と予約も
  テストにします。
- 引数が無いコマンドはプロンプトを出さず、そのまま実行します。
- ステータス行と Settings パレットに、値のスコープと層を表示します。保存の境界は
  `docs/commands.md` に明記します。
- Phase 1 から Phase 5 に分け、各段階でテスト、clippy、fmt を通します。

## 見直しの条件

1. 設定 UI から `settings.json` へ永続化したくなったとき。
2. 範囲を実際に使う編集コマンド（`:d` など）を追加するとき。
3. プラグインの Ex 名が衝突し、名前空間や所有者接頭辞が必要になったとき。
4. パレットの引数プロンプトが煩わしく、インライン入力の方が良いと分かったとき。
5. パレットと Ex の入力欄を統合する要望が強くなったとき。

## 関連する未決定事項

- 最後のペインで `:q` を押したとき、アプリを終了するかエラーにするか。
- `:!`（シェル実行）を許可する場合のケイパビリティと、シェル展開の範囲。
- `|` による連結、`"` によるコメント、`/pattern/` を使った範囲指定を入れるか。
- 範囲の既定値を「現在行」「選択範囲」「文書全体」のどれにするか。
- Select モードで `:` を押したときに `'<,'>` を自動で補うか。
- Ex の履歴をファイルへ保存するか、パレットの履歴と共有するか。
- Ex 名の大文字・小文字を区別するか（初期案は小文字のみ）。
- 設定を UI から永続化するコマンド（`:set --save` など）を用意するか。
- パレットの最近使ったコマンドをセッションを越えて保存するか。
