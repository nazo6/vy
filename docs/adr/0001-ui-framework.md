# ADR 0001: UI フレームワークに GPUI と gpui-kit を採用する

- 状態: 採用
- 日付: 2026-10-22

## 文脈

Vy は、モーダル編集、GPU 描画、Webview
の埋め込み、リモート開発を同時に満たすデスクトップエディタを目指しています。UI
の状態（ペイン構成、ステータスライン、モード、選択範囲）はコアが所有し、クライアントはその状態を描画する層にします。この形にすると、クライアントが使うフレームワークの機能は限られます。一方で、テキスト描画、IME、Webview
の重ね合わせは自前では実装量が大きくなります。

当初は GPUI の採用を前提にしていましたが、wgpu
を使う場合の実装量を懸念する声があり、選定をやり直しました。

## 決定ドライバ

1. Linux、macOS、Windows の3つで動くこと。
2. エディタ本体を Web 技術で作らず、ネイティブ描画にすること。
3. 入力遅延と20万行級ファイルのスクロール性能を優先すること。120fps
   は目標にしますが、必須条件にしません。
4. ネイティブ Webview をペインとして埋め込めること。
5. TypeScript プラグインと、ケイパビリティの強制を前提にすること。
6. コアをヘッドレスにでき、クライアントを差し替えられること。
7. 実質1人から2人の開発で維持できること。実装量と保守コストを最も重く見ます。
8. コアが UI 状態を所有し、クライアントはテキストグリッド、スロット、Webview
   のホストに絞れること。

次の選択肢は、ドライバを満たせないため対象から外しました。

- GTK4 は Windows と macOS で実用になりません。
- Qt は3 OS を満たしますが、C++ のツールチェーンと QtWebEngine
  の配布サイズを受け入れます。
- Tauri などの Web UI は、エディタ本体をネイティブ描画にする方針と合いません。

## 決定

UI フレームワークに GPUI を採用し、部品として gpui-kit / gpui-base を使います。

- `gpui` はバージョンを完全に固定します（`=` 指定）。`gpui-kit` / `gpui-base 0.8.0` の要件に合わせ、`gpui-pre = "=0.3.9"` および `gpui-pre-platform = "=0.3.9"` に固定します。更新は独立した PR で行います。
- Webview は gpui-kit のクレートを使い、`vy-app`
  の中の薄いラッパ越しに呼びます。差し替えられるようにするためです。
- Dock レイアウト、エディタの描画、アクセシビリティの実装は gpui-kit / gpui-base
  を参照します。ただし、コードをそのまま取り込まず、必要な部分だけを使います。
- `gpui-shell` は採用しません。プラグイン API とケイパビリティの強制点は `vy-js`
  で自前に持ちます。API の表面を自分で決め、`backend.ts` と RPC
  を統合するためです。

GPUI に依存してよいのは `crates/vy-app`
だけにします。`vy-proto`、`vy-core`、`vy-js`、`vy-capabilities`
はフレームワークに依存させません。

## 帰結

### 良い面

- Webview
  の埋め込みと、20万行規模のエディタ描画に既存の実装があります。ゼロから作る範囲が小さくなります。
- 3 OS のバックエンドが揃っています。macOS は Metal、Windows は Win32 と
  DirectWrite、Linux は Wayland と X11 です。
- コアが UI 状態を所有するため、フレームワークの宣言的 API
  への依存を小さくできます。上流の変更を受ける範囲が狭くなります。
- テスト用のコンテキストと、ホットリロードの仕組みがあります。

### 悪い面

- `gpui` は 0.2 系で、破壊的変更が続いています。追随の作業が定期的に発生します。
- Windows と Wayland の実装は macOS より新しく、IME と Webview
  の不具合が残る可能性があります。
- ドキュメントが少なく、Zed のソースを読む前提になります。
- gpui-kit
  は第三者の成果物です。方針が変わると、部品の差し替えが必要になります。

### 緩和策

- GPUI への依存を `vy-app`
  に閉じ込めます。差し替えるときの影響を1クレートに抑えます。
- エディタ本体は低レベル API で描き、高レベルな宣言的 API は設定画面などの周辺
  UI に限定します。
- Webview は薄いラッパ越しに使い、wry で作り直せる形にします。
- 3 OS の検証を Phase 1 から CI に入れます。

## 見直しの条件

次のどれかに当てはまったら、この決定を見直します。

1. Wayland か Windows で、IME の前編集か Webview
   の表示不具合が2リリース続けて直らない。
2. 上流の破壊的変更への追随が、週の作業時間の半分を超える。
3. GPUI では要件を満たせない箇所が `vy-app` の3割を超える。

見直す場合も、`vy-core`、`vy-proto`、`vy-js` は変更しません。書き換えるのは
`vy-app` だけです。

## 関連する未決定事項

- Windows の扱い: Phase 1 は対象外としました。Linux と macOS
  で開発し、Windows は Phase 2 以降で扱います（[`roadmap.md`](../roadmap.md)）。
- gpui の固定バージョンをどの頻度で更新するか。
- Webview のフォーカスとキー入力の受け渡しを、どこで切り替えるか。
